# Webinar catalogue (HIR-255)

`/webinars` reads the public Portal catalogue at runtime, so Anne's edits do not require a website rebuild. `/webinars/:id` shows the event and reuses the branded lead form for on-demand access. The Resources navigation points to the catalogue. Existing `/webinar`, `/webinar/view`, `/webinar/cdfa` and `/webinar/cdfa/view` retain their original behavior.

Configure `NUXT_PUBLIC_PORTAL_API_BASE_URL` and allow the website origin in Portal CORS. The static host needs its `/200.html` fallback for event detail routes. The `/webinars` catalogue has a canonical URL and sitemap entry and remains indexable. Individual `/webinars/:id` pages receive `X-Robots-Tag: noindex, nofollow` from nginx on the initial response and matching client metadata. Nginx normalizes escaped path characters before matching the event-detail location, which sets the noindex marker; the snippet's named fallback serves `/200.html` without restarting server rewrites, and the response header remains server-scoped to preserve BasicAuth and server security headers. The rule deliberately excludes `/webinars` and `/webinars/`, including their query-string forms. Their event details update in the browser; static hosting cannot emit fresh event HTML or a true HTTP 404 without a rendering service. No restricted event or recording is baked into website output.

The catalogue API returns only public metadata. Live actions go through the Portal's checked Zoom redirect. A valid branded form submission to `/api/public/webinars/:id/access` creates an event-linked registration and returns a Portal recording path valid for seven days. Repeating an active registration preserves its identity and logical delivery jobs; re-entry after expiry renews access without increasing registration counts. The emailed recording URL carries its opaque capability only in `#access_token`; the detail page removes that fragment immediately, resolves it through `POST /api/public/webinars/:id/access/resolve`, and keeps neither the token nor recording route in browser storage. Expired or invalid links for a currently public On-Demand webinar return to the branded form with a recovery message. Private, archived and missing webinars remain unavailable. The recording route must recheck current visibility and availability on every request. Detail pages set a no-referrer policy and the embedded player and new-tab fallback also suppress referrers. Embedding depends on the final video provider; the page includes a new-tab fallback. Provider-level access restrictions are needed to prevent sharing a provider URL after an authorized viewer reaches it.

HIR-259 adds durable registration email and HubSpot jobs in Portal. Provider settings, approved email copy and actual Zoom/HubSpot acceptance are tracked separately in [HIR-615](https://linear.app/hirebrains-io/issue/HIR-615/webinars-configure-email-delivery-hubspot-properties-and-native-zoom); delivery remains gated until configured. Zoom owns native Live registration and reminders. Existing legacy lead flows stay functional.

The recording fallback is a button that opens a separate tab with no opener or referrer. Its capability stays out of outbound anchor URLs collected by enhanced analytics.

Verify catalogue loading/error/empty states, live Zoom CTA, past events without recordings, on-demand lead capture and player fallback, valid/expired/malformed emailed fragments, route changes after viewing, keyboard navigation, mobile layout, legacy URLs, and Portal rejection of Partner-Only IDs. Provider delivery and restricted hosting settings require separate live acceptance.
